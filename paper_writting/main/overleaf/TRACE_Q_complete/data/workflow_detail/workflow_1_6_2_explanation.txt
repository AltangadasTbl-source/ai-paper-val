Workflow 1.6.2: roles, decisions, branches, and limits
Documentation prepared from the local normative workflow and role presets, 2026-10-22.
This document describes the workflow; it does not execute a paper review. Paths below beginning with extraction/, checkers/, statistics/, relationships/, screening/, verification/, or quality/ are relative to a reviewed package's .ai_paper_validation/review_1_6_2/ directory. Source references refer to the supplied workflow1.6.2/ tree, not to historical execution evidence. The accompanying source_locators.csv gives exact file and line references; role_decision_matrix.csv records the handoffs in tabular form.

1. What the workflow promises

The unit of work is one supplied paper package: main article plus all supplied supplements, protocol/SAP versions, and structured files. The goal is to prepare source-grounded quantitative reporting candidates for later adjudication. It is not a general assessment of clinical value, novelty, misconduct, study validity, or the merits of an alternative analysis. Only package evidence is allowed. The system does not claim that a candidate is a confirmed scientific problem. It does not assign severity or a final correction. [S01, S02]

There are ten named specialist presets, but eleven mandatory specialist stages: the statistical-review preset is instantiated separately for passes 1 and 2. The current coordinator is additional, so the minimum specified execution has one coordinator plus eleven distinct specialist runtime IDs. A second inclusion-screen agent is conditional on new pass-2 findings; shards and repairs can add further agents. Each mandatory specialist stage must start fresh, even if its scope is explicitly not applicable. Fresh agents isolate execution histories; they do not establish independent models or blinded replication. All roles use one recorded run model (default gpt-6.1-sol), with medium effort for curation, mapping, numeric/cross-source checks and reporting, and high effort for the coordinator, statistics, screening, rechecking and auditing. This is the current normative specification, not independent proof of what model every historical package used. [S03, S04, S05]

2. Coordinator and source preparation

The coordinator owns sequencing, exact scope assignments, canonical merging, stable candidate IDs, final classification writeback and completion checks. Before scientific work it verifies the routing preflight and role presets, records tools and compute device, hashes direct sources, starts the timing record and execution manifest, and defines a package-specific planning target. If the default model is unavailable, the specification requires the user to name an exact replacement; it forbids silently choosing a substitute. CPU is the default for rendering/OCR; GPU use needs an explicit user request. These operational requirements describe the actual review pipeline and are not prerequisites for this documentation task. [S03, S06]

The reuse_asset_curator inventories direct sources and reusable text, OCR, page maps, rendered pages and table/workbook extractions. It maps every derivative to exact source units, hashes reused artifacts and marks their fitness USABLE, PARTIAL, STALE, DUPLICATE or UNREADABLE. It classifies source content as REPORT or PLAN; a protocol packaged as a supplement remains PLAN. A mixed bundle needs location-level clarification. Its outputs are source_inventory.md, evidence_asset_inventory.md, source_coverage.md and the before-hash files, with run-state initialization coordinated to avoid overlapping writes. The curator does not diagnose candidates. [S07]

Reuse changes the cost of acquisition, not the discovery boundary. Old checker outputs, candidate lists, screening/classification decisions and reports are preserved but are forbidden scientific inputs for discovery. Every source unit has either usable reused coverage or a fresh-required assignment: reusable + fresh-required = total. Every unit must ultimately be mapped: mapped = total. Missing extraction software never authorizes dropping pages. Available text, targeted rendering/OCR and visual inspection must close the scientific coverage gap; any remaining inability must be documented and cannot honestly be called complete coverage. A reusable-derivative gap can remain a limitation after the direct-source scientific gap is closed. [S08, S09]

The coordinator creates coverage_manifest.md before mapping. Each row has a disjoint exact scope, stage, unique shard ID, one artifact path and status. Candidate-stage scope enumerates every assigned C ID; statistical-pass scope enumerates S IDs. A no-applicable scope is explicitly documented COMPLETE, not silently omitted. Sharding is allowed only to bound context, never to cap findings. The settings prescribe bounds of 200,000 normalized text characters, 32 rendered pages, 120 relationships and 60 candidates per recheck shard; these are operational context bounds, not claims about scientific adequacy. [S10, S11]

3. Two mappers build evidence, without diagnosing candidates

The main_quantitative_mapper reads the disjoint assigned main-paper units. It maps counts, denominators, percentages, rates, person-time, summaries and dispersion, estimates, intervals, P values, test statistics, standard errors, population/time/contrast/model labels, units, reference directions, figure/table labels, footnotes and matching narrative claims. It uses reused assets as locators, inspects uncovered direct-source units and marks no-applicable units explicitly. It writes extraction/main_quantitative_evidence.md or unique parts. It neither selects candidates nor samples only primary/significant results. [S12]

The support_quantitative_mapper runs concurrently on disjoint support units: supplements, plans, DOC/DOCX, workbooks and CSV. It maps the corresponding relationships and matches main-paper keys; for workbooks it distinguishes formulas from cached/displayed values. It reads every assigned plan or administrative unit rather than assuming such pages lack quantitative evidence. It writes extraction/support_quantitative_evidence.md or parts, including a nonempty not-applicable record when appropriate. [S13]

The merged evidence supports stable N001... identifiers for numeric/reporting relationships and S001... identifiers for inferential relationships. These relationship IDs are not candidate IDs. A relationship can yield a successful reconciliation, a named missing definition, an excluded observation or a finding. Both N and S may be attached when separate tracking is useful, but evidence should be cross-referenced rather than duplicated. [S14]

4. Three checkers run concurrently after mapping

The numeric_consistency_reviewer checks participant flow, randomized/treated/analyzed/followed-up counts, events, numerator-denominator-percentage relations, row/column/subgroup totals, repeated counts and effect-measure identity. It builds or extends relationships/numeric_relationship_inventory.md, records reconciled checks, and writes checkers/numeric_consistency.md. Apparent issues passing self-screen receive F-NUM-... IDs. [S15]

The cross_source_consistency_reviewer matches population, time, contrast, model, measure, analysis set and precision before comparing values. It checks matched results across the abstract, narrative, tables, figures, captions, supplements and structured files; it also compares reported analysis/outcomes with plans and examines plan-internal statistical elements. It compares criterion lists item by item. Its output checkers/cross_source_consistency.md contains F-XS-... findings and excluded observations. A mismatched analysis population or time point is not a valid numeric comparator merely because the numbers look similar. [S16]

Statistical pass 1 uses a new high-effort statistical_consistency_reviewer. It creates the S inventory and checks interval ordering and estimate containment, direction, estimate/CI/P/test compatibility, superiority/noninferiority/equivalence against stated margins, multiplicity/interim/stopping rules, and the logic connecting the described method to the reported result. Sample size reproduction is in scope when inputs are supplied. It must not invent sidedness, degrees of freedom, covariance, variance estimator or an estimand mapping from convention alone. Diagnostic approximations are labeled as such. Outputs are statistics/relationship_inventory.md and checkers/statistical_pass_1.md, with F-ST1-... findings and PASS_1_COMPLETE records. [S17]

Each checker applies the same self-screen. A qualifying observation becomes a finding, with exact locations, printed values, rule/calculation, document roles, focus area, proposed domain, qualifying route, affected result, relevant context and alternatives. An apparent issue not emitted is recorded once in an Excluded observations table with a single reason code, but no F ID. Checks that simply reconcile belong in relationship records, not the exclusion table. This distinction matters because pass 2 and the auditor revisit apparent issues that the first checkers suppressed. [S18]

5. The inclusion decision is a specified rule, with judgment in its application

The exact logic is: reproduced AND (Route A OR (B1 AND B2 AND B3)). Reproduced means reading the exact supplied source correctly and retaining the discrepancy under the stated arithmetic, statistical or logical rule. Merely detecting different strings is insufficient. [S19]

Route A has five always-register categories: (1) interval-versus-P/test incompatibility or point estimate outside its interval; (2) a printed sign/digit/decimal/reference-direction slip that changes the reading; (3) count-denominator-percentage incompatibility within one display, including a baseline table; (4) a printed estimate/interval not reproduced by a method that does reproduce the other rows of that display; and (5) specified planned-versus-reported outcome-status/composite changes, an analysis called prespecified but absent from the supplied plan, or an unreported planned primary/key secondary analysis. A reproduced Route A observation does not also have to pass Route B. Only NOT_REPRODUCED or DUPLICATE_OF_INCLUDED can remove it. Category 1 is explicitly exempt from the rounding rule. If the source attributes the CI and P value to different analyses, that becomes an alternative interpretation on the card rather than automatic removal under this workflow's policy. This is an inclusion policy; it is not a theorem that every retained CI–P pair is scientifically incompatible. [S20]

Route B requires all three: B1 in the quantitative scope and not peripheral; B2 not immediately resolved by a statistically literate reader's immediate context; B3 plausibly changes interpretation of a named result or the value extracted for evidence synthesis. These are source-grounded judgment calls, not deterministic string tests. The four focus areas are counts/denominators, estimate/test logic, statistical-method logic and planned-versus-reported statistical design. The doubt rule instructs agents to exclude ambiguous wording/terminology/symbol concerns but register doubtful printed numbers, intervals, P values, counts and plan–report elements for later review. This procedural tie-breaker does not eliminate the reproduction requirement. [S21]

Scope is tiered. Primary/key secondary results, abstract/Key Points discrepancies, result misattributions and quantity-changing labels can qualify. Plan–report comparisons include analysis specification, endpoint definition/window/hierarchy, outcome status/composite components and randomized intervention dose/duration. Copies of baseline descriptive values, individual-time counts, pointers, sites, recruitment calendars and peripheral plan details are normally excluded unless they change a primary/key secondary result, analysis-population size or decision rule. A mismatch inside one baseline count/percentage display is nevertheless Route A category 3. Apply the explicit Route A exception when it conflicts with a generic exclusion description. [S22]

Display precision is not raw subtraction or a 5-percentage-point rule. Give every displayed numeric input its half-unit rounding interval, propagate those intervals through the stated calculation, and give the displayed comparator its own half-unit interval. Let g be the nonnegative gap between recomputed and displayed intervals; g = 0 if they overlap. For nonzero printed/reference value v, define r = g/abs(v). If g = 0 or r <= 0.05, use ROUNDING_OR_DISPLAY_PRECISION. If r > 0.05, or g > 0 with v = 0, the numeric discrepancy is reproduced, subject to the remaining inclusion logic. Two printed copies use the gap between their half-unit intervals and a designated reference copy. Record both the recomputed interval and r. Category 1 interval-versus-P/test conflicts bypass this rounding screen. P = 0 or .000 by itself is excluded; an independent contradiction is needed. [S23]

For illustration, two one-decimal printed copies 10.0 and 10.6 have intervals [9.95,10.05] and [10.55,10.65], giving g = 0.50 and r = 0.05 relative to 10.0: excluded at the boundary. If the second copy is 10.7, g = 0.60 and r = 0.06: the mismatch passes this numeric screen but still needs a qualifying route. These are teaching examples, not observations from a paper. The 5% policy is a screening heuristic mandated by this workflow, not a p-value, clinical importance cutoff or calibrated detection guarantee.

Other reason codes are NOT_REPRODUCED, NOTATION_OR_TYPOGRAPHY, TERMINOLOGY_OR_WORDING, MODEL_VERSUS_CRUDE, CONTEXT_RESOLVES, CONDITIONAL_OR_UNREPORTED, PERIPHERAL_COMPARISON, OUT_OF_FOCUS and DUPLICATE_OF_INCLUDED. MODEL_VERSUS_CRUDE protects an adjusted/model-based estimate from being treated as inconsistent merely because it differs from a crude recomputation, unless the source calls it crude/unadjusted. A missing method detail with no printed contradiction is insufficient. Each exclusion has one code; the log is not a severity scale. [S24]

6. Independent screening, deduplication and stable registration

After all three initial checkers finish, a fresh high-effort inclusion_screener rereads every finding's source locations and independently applies the inclusion rule. It writes the single screening/inclusion_screen.md table. INCLUDE uses MEETS_THRESHOLD and initially PENDING for the candidate ID; SCREENED_OUT uses one reason code. Duplicate findings point to the retained issue and preserve all affected locations. No target finding count or comparison with other papers is permitted. [S25]

Deduplication occurs before stable registration: the same failed rule for the same evident cause across rows/outcomes/documents is one issue with every affected location. Different rules or independent causes warrant separate candidates. Several findings can support one included issue. The coordinator then assigns C001... in source order, writes candidate_ledger.md and writes those IDs back to included screening rows. F IDs retain checker provenance; C IDs identify durable review objects. Later findings are appended without renumbering. Once a C ID exists, it is never deleted, merged away or hidden, even if later evidence questions inclusion. Zero candidates is valid after complete coverage. [S26]

7. Relationship classification and review-domain routing

At registration the coordinator assigns a provisional relationship type, all relationships, one domain and compared document roles. Roles are assigned by content, not filenames. P_R means a conflict between REPORT and PLAN and routes to protocol_report; it does not itself imply a protocol violation. P_P means solely plan-internal conflict and routes to plan_material. S_C means between distinct REPORT documents; S_W means within one REPORT document. S_C/S_W route to statistical_results for counts/estimates/intervals/tests/methods, or report_internal_inconsistency when the conflict prevents identifying which outcome/time/population/comparison a number belongs to. Mere wording differences are not enough. [S27]

A candidate involving multiple genuine conflicts lists every relationship and chooses the primary by P_R > P_P > S_C > S_W. A document that merely corroborates one side is not another conflict: a protocol confirming the intended value of an internal report discrepancy does not automatically make it P_R. Uncertain roles or a potentially disclosed amendment go into Classification ambiguity. The rechecker confirms/corrects classifications, the auditor audits them, and the coordinator writes the final values back to the ledger. This classification routes later review; it is not adjudication or severity. [S27, S28]

8. Recheck and the second statistical pass

The evidence_rechecker uses a fresh high-effort agent for every stable candidate's exact source locations, not OCR as final authority. It separately records location found; source and comparator text matched; rule applicable; calculation/logic reproduced including rounding; necessary inputs and exact omissions; source-grounded alternatives; observation versus inferred explanation; remaining human question; and content-based classification. PDF locations use truthful #page=N links; workbook evidence names sheets/cells, CSV evidence rows/columns and DOCX evidence stable paragraph/table locations or a derived PDF page. [S29]

It assigns exactly one evidence state: reproduced; reproduced_after_transcription_correction if corrected transcription/location still supports the discrepancy; or not_reproduced if correct source reading reconciles it. A missing definition or failed subcheck is recorded explicitly, not converted into deletion. There is no fourth indeterminate evidence-state code: unresolved scientific interpretation belongs in the missing-input/alternative/human-question fields. In particular, inability to reproduce because an input is missing should not be casually equated with evidence that the printed values reconcile. The normative state definitions do not fully specify every missing-input case; document the factual limitation rather than pretending it is resolved. [S30]

Statistical pass 2 is a different fresh high-effort instance of the statistical reviewer. It starts after the complete cross-lane ledger, initial screening log and recheck exist, then revisits every S relationship using those artifacts. It reconciles numeric/cross-source implications and checks all checker Excluded observations rows against Route A and the rounding rule. It does not re-emit an observation already represented in the screening log. Every S relationship needs PASS_2_COMPLETE even when there is no finding or a named missing definition prevents mechanical reconciliation. Because pass 2 sees earlier outputs, call it a sequential second review, not blinded replication. [S31]

If no new findings emerge, pass 2 proceeds to audit. If it emits F-ST2 findings, a different fresh inclusion_screener_pass_2 reads those findings and writes its own working notes; the coordinator appends decisions to the canonical screening table. Included issues are appended as new C IDs, classified and rechecked. No mandatory third full statistical pass is specified. New candidate IDs must be included in subsequent audit/report/coverage artifacts. [S32]

9. Audit, repair loops and what completion means

The quality_control_auditor receives the full extraction/relationship/checker artifacts, all excluded observations, both statistical passes, screen log, ledger, recheck, coverage, source coverage, classifications and execution manifest. It audits inclusions and exclusions in both directions, classifications/precedence, evidence states, missing evidence-card fields, unsupported assumptions, pagination, links, duplication patterns and bounded downstream-impact language. Every existing C ID receives Inclusion audit: CONFIRMED or QUESTIONED with a reason; neither is a final scientific validity judgment. [S33]

A finding screened out incorrectly may be rescued by an appended audit row. A new auditor finding receives F-QA-...; the coordinator registers a new C ID and obtains its recheck. Audit history is appended rather than silently overwritten. The phrase 'one screening decision per finding' means one initial/pass-2 decision plus, where needed, an explicit audit revision; the validator permits these paired rows and resolves summaries using the audit row. An initially included finding cannot subsequently be screened out. A doubtful registered candidate stays in the ledger and report with QUESTIONED or not_reproduced evidence information. [S34]

There is a wording tension in the auditor preset: it says 'Reject any stable ID' based solely on display-zero P, while the same preset forbids deleting/suppressing IDs and the canonical contract and validator prohibit changing an included finding to screened-out. The consistent operational reading is to question its inclusion and retain its stable record; do not describe the workflow as deleting such candidates. This is documentation of the tension, not a modification to the workflow. [S35]

The report_generator assembles every C ID into final_report_1_6_2.md, copying classification fields and preserving source evidence, reasoning, calculations, affected result, alternative interpretations, mechanical facts and bounded potential impact. It includes the screening/domain summaries, full candidate index, limitations, source integrity, agent execution and timing. Screened-out pre-registration findings appear in summary/logs, not as candidate cards. A zero-candidate report still documents scope, coverage, exclusions and limitations. Cards say Pending Human Adjudication and contain no human adjudication fields; those belong in the later workbook. The coordinator finalizes timing, hashes sources/assets again, renders standalone HTML, removes the temporary fallback environment and runs the validator. [S36]

Correctable validation failures loop back to the responsible artifact/coverage repair and are rerendered/revalidated until PASS. Additional repair agents have distinct IDs and retain their role's model/effort class; they cannot stand in for an omitted mandatory stage. No fixed retry count, timeout, exponential backoff or promise of eventual success appears in the specification. A planning target can be exceeded with reasons; it never permits dropping sources, second passes or candidates. If repair needs another model response after the recorded finish, timing and execution metadata are updated. Unrepairable missing evidence prevents an honest claim that all mandatory completion gates passed. [S37]

Mechanical completion requires identical ledger/recheck/audit/report C-ID sets, full registered S-ID coverage in both passes, complete classification, resolved local links, unchanged source/reused hashes, prescribed fresh-agent manifests, tooling cleanup and a valid standalone HTML report. The validator enforces file/schema/set/count/link/hash/manifest properties and checks declared source-coverage arithmetic. Its S-pass checks look for relationship IDs in both pass artifacts and completion markers in the inventory. It does not independently read every source page, rediscover missing relationships or prove that the mathematical/scientific reasoning is correct. Therefore PASS means the machine-checkable contract passed, not perfect coverage in a semantic sense, calibrated sensitivity/specificity, clinical importance, absence of missed issues or successful human adjudication. Those stronger claims need separate evaluation. [S38]

10. Intended human responsibility versus the supplied completed-run record

The intended endpoint of Workflow 1.6.2 is a reviewable evidence package. Humans decide the ultimate disposition and substantive interpretation; the workflow's inclusion state, evidence state and inclusion audit do not substitute for that responsibility. The report deliberately leaves adjudication fields to a later workbook. [S39]

However, reviewer_runs_raw/README.md explicitly says the supplied eight completed v2.4.1 workbooks were produced by Claude Opus 5.5 high-effort agent sessions, under labels R_A and R_Bulun, and that no person reviewed any candidate. Eight original sessions were followed by two 2025 addendum sessions; the latter's 24 candidates per label were merged into the 2025 files. Each reviewer session worked alone. The reviewers read source PDFs before each candidate card and could inspect the supplied workflow scope, so their task is a post-pipeline review with access to cards, not a blind independent search of an unflagged paper set. [S40]

The user subsequently confirmed that the copied workbooks were later reviewed by humans. The actual chain must therefore distinguish two layers: raw Claude review runs -> copied workbooks -> later human review. The raw README establishes the first layer; the user's clarification establishes the later human-review step. Raw-run agreement remains same-model run agreement, not human inter-rater reliability. The later human review must not be erased by calling the final copied workbooks entirely AI reviews, but it also must not retroactively turn raw Claude-written rationales into human-authored notes. Fresh sessions and separate folders reduce direct exchange; they do not remove shared-model blind spots. The raw README records annotation exposure, possible overconfidence (zero discuss decisions), missing plans and pending desktop Excel validation. These describe the raw-run record and do not establish what the subsequent humans did or did not resolve. The deck should distinguish the intended review interface, the implemented workflow specification, raw AI note authorship and the user-confirmed subsequent human review. [S40, S41; user clarification relayed by coordinator on 2026-10-22]
